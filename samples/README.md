# Fixture scenario

Written for: whoever runs the demonstration (Mohan, or anyone watching it).

**Fictional applicant:** "Fictional Demo Applicant", demo-only person applying for an
Income Certificate from the mock eDistrict Kerala portal for the purpose
"Bank Loan". District Ernakulam. All identifiers (Aadhaar-shaped number, ration
card number, mobile number, tax receipt numbers) are synthetic patterns chosen
to satisfy the portal's own format checks (e.g. Aadhaar must be exactly 12
digits if provided) — none correspond to real people, real documents, or real
government identifiers. The email uses the `.invalid` TLD (reserved by RFC
2606 for exactly this purpose — guaranteed non-deliverable and non-real).

**application.sample.json** — every required field filled, all 6 documents
attached (5 required + the optional affidavit), should validate cleanly and
run to the Stage 3 review screen without any blocking issue.

**application.invalid.json** — identical to the valid sample except the
required "landtax" (Land Tax Receipt) attachment is missing. This is the one
deliberate, isolated failure used to prove the app's pre-flight validation
actually rejects an incomplete case instead of opening the browser anyway.

**documents/** — generated by `scripts/generate-fixtures.ts`. Five PDFs
(pdf-lib) and one PNG (a Playwright screenshot of a plain HTML placeholder —
no canvas/font-rendering dependency needed). Every file visibly carries both
"SAMPLE — FOR SOFTWARE TESTING ONLY" and "NOT A GOVERNMENT-ISSUED DOCUMENT",
and none contains a real seal, signature, or scannable identity code. Each
file is verified to actually decode right after generation (PDF: reloaded and
page-counted with pdf-lib; PNG: reloaded as a real <img> in headless Chromium
and checked for non-zero natural dimensions).

Regenerate at any time with: `npx tsx scripts/generate-fixtures.ts`
